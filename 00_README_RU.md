# MK15 Port Inspector 1.0.0

Диагностическое Android-приложение для SIYI MK15. Первая задача — без root определить фактический канал физического тумблера SA и показать его живое значение на экране.

## Автоматические журналы с Windows

После каждого запуска BUILD_WINDOWS.bat и RUN_PROTOCOL_SELFTEST.bat создаётся отдельный каталог:

    runs\build_YYYYMMDD_HHMMSS\
    runs\selftest_YYYYMMDD_HHMMSS\

Журнал начинает записываться до запуска основного сценария. Поэтому сохраняются даже ошибки синтаксического разбора PowerShell, ошибки поиска JDK/SDK и ранние сбои Gradle.

В каталог запуска попадают console.log, result_code.txt, RUN_SUMMARY.txt, git_status_before_publish.txt, publish.log и, если APK успел появиться, каталог artifacts с APK и SHA256.

В конце сценарий автоматически делает git add только своего runs/<id>, создаёт диагностический коммит и пытается отправить его в origin/main. Чужие локальные изменения автоматически не добавляются.

Если сеть или авторизация GitHub недоступны, каталог и локальный коммит остаются на компьютере. После восстановления доступа достаточно запустить:

    PUBLISH_LAST_RUN.bat

## Почему первая локальная сборка не стартовала

Первый tools/build_windows.ps1 содержал кириллицу в UTF-8 без BOM. Windows PowerShell 5.1 интерпретировал такой файл в старой системной кодировке, из-за чего текст превратился в mojibake и парсер начал видеть ложные синтаксические ошибки.

Исправление: все исполняемые Windows BAT/PowerShell-сценарии теперь ASCII-only. Русская документация остаётся в Markdown и не участвует в разборе PowerShell.

## Безопасность аппаратного теста

SIYI предупреждает, что выдача RC-каналов через 0x42 использует тот же интерфейс, что и телеметрия. Первую проверку проводить только на столе, не в полёте и без работающей силовой части. Перед тестом закрыть QGroundControl и другие программы, которые могут занимать USB COM.

Остальная постановка, протокол и критерии приёмки описаны в 01_FINDINGS.md, 02_TASK_SCOPE.md, 03_TESTS.md и 04_PROGRESS.md.
