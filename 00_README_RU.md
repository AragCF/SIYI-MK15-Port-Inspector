# MK15 Port Inspector 1.0.0

Диагностическое Android-приложение для SIYI MK15. Первая задача — без root определить фактический канал физического тумблера SA и показать его живое значение на экране.

## Автоматические журналы с Windows

После каждого запуска BUILD_WINDOWS.bat и RUN_PROTOCOL_SELFTEST.bat создаётся отдельный каталог:

    runs\build_YYYYMMDD_HHMMSS\
    runs\selftest_YYYYMMDD_HHMMSS\

Журнал начинает записываться до запуска основного сценария. Поэтому сохраняются даже ошибки синтаксического разбора PowerShell, ошибки поиска JDK/SDK и ранние сбои Gradle.

В каталог запуска попадают console.log, result_code.txt, RUN_SUMMARY.txt, git_status_before_publish.txt, publish.log и, если APK успел появиться, каталог artifacts с APK и SHA256.

В конце сценарий автоматически делает git add только своего runs/<id>, создаёт диагностический коммит и пытается отправить его в origin/main. Чужие локальные изменения автоматически не добавляются.

Если сеть или авторизация GitHub недоступны, каталог и локальный коммит остаются на компьютере. После восстановления доступа достаточно запустить:

    PUBLISH_LAST_RUN.bat

## Почему первая локальная сборка не стартовала

Первый tools/build_windows.ps1 содержал кириллицу в UTF-8 без BOM. Windows PowerShell 5.1 интерпретировал такой файл в старой системной кодировке, из-за чего текст превратился в mojibake и парсер начал видеть ложные синтаксические ошибки.

Исправление: все исполняемые Windows BAT/PowerShell-сценарии теперь ASCII-only. Русская документация остаётся в Markdown и не участвует в разборе PowerShell.

## Безопасность аппаратного теста

SIYI предупреждает, что выдача RC-каналов через 0x42 использует тот же интерфейс, что и телеметрия. Первую проверку проводить только на столе, не в полёте и без работающей силовой части. Перед тестом закрыть QGroundControl и другие программы, которые могут занимать USB COM.

Остальная постановка, протокол и критерии приёмки описаны в 01_FINDINGS.md, 02_TASK_SCOPE.md, 03_TESTS.md и 04_PROGRESS.md.


## Версия 1.1.0 — универсальный поиск источника SA

Добавлен программный переключатель транспорта:

- AUTO / все безопасные;
- USB COM / CP210x;
- UDP;
- Bluetooth SPP;
- UART /dev/ttyHS0;
- Android Input (пассивный).

В AUTO приложение пытается параллельно открыть доступные исследовательские пути. Байтовые потоки разбираются отдельными экземплярами SIYI parser, поэтому данные разных транспортов не смешиваются.

### Switch Finder

Алгоритм работы:

1. Нажать «1. Снять базу» либо использовать автоматически снятую стартовую базу.
2. Физически перевести SA в другое положение.
3. Нажать «2. Я переключил SA — сравнить».
4. Повторить ещё несколько раз, переводя SA в другое положение.

Каждый снимок включает доступные:
- значения RC CH1..CH16 по каждому транспорту;
- Android KeyEvent и MotionEvent;
- счётчики и последние сырые байты USB/UDP/Bluetooth/UART;
- /sys/class/switch;
- экспортированные GPIO;
- extcon;
- /proc/interrupts;
- состояние известных tty-узлов.

Кандидаты получают вес. Изменение конкретного RC-канала, Android axis/key, switch/GPIO имеет существенно больший вес, чем фоновые byte/interrupt-счётчики. При повторных раундах источник, который стабильно меняется вместе с SA, поднимается вверх списка.

### Что это не обещает

Обычный APK не обходит SELinux/root. Если /dev/ttyHS0 закрыт правами, приложение только зафиксирует это. Bluetooth SPP и UDP являются исследовательскими транспортами: их доступность и фактическая связь с SIYI Datalink должны быть подтверждены на конкретном MK15.


## Версия 1.2.0 — отчёт без ADB

Для человека с пультом больше не требуется компьютер с ADB, чтобы передать результат исследования.

В приложении есть три кнопки:

- **ZIP → Download** — формирует новый полный ZIP и кладёт копию в `Download/MK15PortInspector/`. Это понятное место для File Explorer. При наличии ADB этот же каталог можно забрать командой `adb pull`.
- **ZIP → флешка/файл…** — формирует ZIP и открывает системный выбор файла Android. Если флешка подключена и видна системе, пользователь выбирает её как место сохранения.
- **ZIP → thesystem** — формирует ZIP и отправляет его POST-запросом на `https://thesystem.pro/?action=siyi_receive`.

Рабочая копия каждого сформированного ZIP сохраняется также в `Android/data/com.mk15.portinspector/files/reports/`.

ZIP содержит не только видимый текст экрана, но и:
- таблицу каналов;
- mapping и текущий предполагаемый канал SA;
- всю историю Switch Finder;
- экранный и повторный полный системный скан;
- динамический снимок транспортов/Input/GPIO/switch/extcon/interrupts;
- журнал сеанса;
- постоянный runtime-журнал.

### Формат приёма на thesystem

`multipart/form-data`, файл в поле `report`, MIME `application/zip`.

Дополнительные поля: `report_id`, `app_version`, `package`, `device`, `android`, `transport`, `sa_channel`, `finder_rounds`.

Приложение считает HTTP 2xx успешной доставкой и показывает код/краткий ответ сервера прямо на экране.
