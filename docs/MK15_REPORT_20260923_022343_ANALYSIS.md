# Разбор реального отчёта MK15_Report_20260923_022343_v1.2.0

## Контекст опыта

По уточнению оператора, в актуальном опыте исследовались не SA, а физические кнопки **C** и **D**. Последовательность: C-D-C-D-C-D; между нажатиями оператор нажимал кнопку сравнения в приложении. Ранее также двигался центральный ползунковый переключатель.

## Что подтверждено отчётом

- Устройство: QUALCOMM MK15, Android 9 / API 28.
- Приложение 1.2.0 сформировало ZIP автономно.
- Сохранение через Android file picker сработало.
- Предыдущая отправка в thesystem получила HTTP 200.
- Встроенный CP2102 виден Android USB Host: VID 10C4, PID EA60.
- В отчёте USB permission для CP2102 отсутствовало.
- /dev/ttyHS0, /dev/ttyHS1 и /dev/ttyHS2 видны приложению как readable=true, writable=true.
- Есть Linux input device `gpio-keys` (event3).
- Android KeyEvent и MotionEvent от тестируемых C/D в журнал не попали.
- Во время этого сеанса AUTO был выбран в интерфейсе, но транспортные sessions оставались disconnected; `rc.last.source=none`, CH1..CH16 не имели живых значений.

## Почему 1.2.0 не могла надёжно увидеть C/D

Кнопки C/D являются моментальными. Снимок выполнялся после отпускания кнопки. Если RC-канал при нажатии кратковременно уходит из исходного значения и после отпускания возвращается, обычное сравнение «до/после» видит одинаковый итог и теряет событие.

Кроме того, оператор не выполнял отдельное подключение транспортов/RC-потока, поэтому в отчёте нет SIYI 0x42 данных.

## Отдельная интересная улика: центральный ползунковый переключатель

В одной из серий первые два сравнения показали синхронное переключение группы записей `system.gpio.debug.101..108` (примерно gpio100..gpio107) из режима input/low в output/high/pull-down и обратно.

Это может быть связано с центральным ползунковым переключателем, поскольку оператор сообщил, что двигал его. Пока это **не доказательство конкретного GPIO**: меняется сразу группа pinctrl-состояний, а не один устойчивый логический бит.

## Что изменено в 1.3.0

- AUTO теперь пассивно подключает доступные пути сам при запуске.
- Исследуются ttyHS0, ttyHS1 и ttyHS2.
- Случайное несвязанное Bluetooth-устройство в AUTO не подключается.
- Добавлен пассивный reader доступных `/dev/input/event*`.
- Добавлена отдельная кнопка «АВТОПОИСК C/D (20 Гц)».
- Для RC сохраняются `last/min/max/changeCount/samples`; моментальное нажатие остаётся заметным даже после возврата канала в исходное состояние.
- На экране появились отдельные «C → сравнить» и «D → сравнить».
- В ZIP теперь сохраняется полный список изменений каждого раунда, а не только восемь верхних кандидатов.
- Рейтинг сначала учитывает содержательность/вес сигнала и только затем число совпадений. Фоновый IRQ больше не должен автоматически побеждать полезный RC/Input-сигнал.

## Следующий опыт

1. Запустить 1.3.0.
2. Разрешить USB-доступ к CP2102, если Android покажет запрос.
3. Нажать «АВТОПОИСК C/D (20 Гц)».
4. Выполнить не менее 8–12 действий, чередуя C и D.
5. После C нажимать «C → сравнить», после D — «D → сравнить».
6. Сформировать ZIP и отправить в thesystem.

После этого можно будет отдельно сопоставить кандидатов C и D и определить программный источник.
