# Техническое задание: приём диагностических ZIP-отчётов SIYI MK15 в TheSystem

## 1. Назначение

Необходимо доработать TheSystem для приёма диагностических ZIP-отчётов от Android-приложения **SIYI MK15 Port Inspector**.

Приложение отправляет отчёт напрямую с пульта SIYI MK15 на адрес:

`POST https://thesystem.pro/?action=siyi_receive`

Сервер должен принять ZIP-файл, безопасно сохранить его в каталоге `/data/siyi/` с привязкой к дате и времени приёма и вернуть приложению короткий понятный ответ.

## 2. Точка входа

Метод: `POST`

URL: `https://thesystem.pro/?action=siyi_receive`

Нужно добавить обработчик `siyi_receive` в существующую архитектуру TheSystem в стиле проекта.

Запросы другими HTTP-методами должны отклоняться с кодом `405 Method Not Allowed`.

## 3. Формат входящего запроса

Тип запроса: `multipart/form-data`.

### 3.1. ZIP-файл

Основной файл приходит в поле `report`.

Ожидаемый MIME: `application/zip`.

На стороне PHP файл доступен как `$_FILES['report']`.

### 3.2. Дополнительные текстовые поля

Приложение может передавать: `report_id`, `app_version`, `package`, `device`, `android`, `transport`, `sa_channel`, `finder_rounds`.

Эти поля не являются обязательными для сохранения ZIP. Их следует нормализовать, журналировать и при необходимости сохранять в метаданных. Не использовать их напрямую как пути/имена каталогов.

## 4. Каталог хранения

Базовый каталог: `/data/siyi/`.

Рекомендуемая структура: `/data/siyi/YYYY-MM-DD/`.

Имя ZIP: `YYYY-MM-DD_HH-mm-ss_<unique>_<original-safe-name>.zip`.

Дата и время — серверное время фактического приёма. Исходное имя файла очищать от `/`, `\`, `..`, управляющих и опасных символов. Клиент не должен иметь возможность выйти за пределы `/data/siyi/`.

## 5. Проверки файла

Перед сохранением проверить:

1. наличие `$_FILES['report']`;
2. `UPLOAD_ERR_OK`;
3. `is_uploaded_file()`;
4. размер > 0;
5. размер <= лимита;
6. ZIP-сигнатуру/тип;
7. возможность открыть архив через `ZipArchive::open()` без распаковки.

Рекомендуемый стартовый лимит: `50 MB`. Также согласовать `upload_max_filesize` и `post_max_size`.

ZIP автоматически не распаковывать.

## 6. Безопасное сохранение

Рекомендуемый порядок:

1. создать каталог даты;
2. сформировать безопасное уникальное имя;
3. сохранить как временный `.part`;
4. использовать `move_uploaded_file()`;
5. после успешной записи переименовать в `.zip`;
6. проверить существование и ненулевой размер.

Рекомендуемые права: каталог `0750/0755`, файл `0640/0644`, в соответствии с пользователем PHP-FPM/web-сервера.

## 7. Метаданные

Желательно сохранять рядом `.meta.json` с: `received_at`, IP, оригинальным и сохранённым именем, размером, SHA-256 и всеми текстовыми полями приложения.

После сохранения ZIP обязательно вычислить SHA-256 и вернуть его в ответе.

## 8. Ответ метода

Android-приложение считает любой HTTP `2xx` успешной доставкой.

Рекомендуемый успех: HTTP `200` или `201`, JSON:

```json
{
  "ok": true,
  "id": "2026-09-22_17-15-03_a81f",
  "received_at": "2026-09-22T17:15:03+03:00",
  "file": "2026-09-22_17-15-03_a81f_MK15_Report_20260922_171500_v1.2.0.zip",
  "size": 123456,
  "sha256": "..."
}
```

Ошибки: `400/422` для плохого запроса, `413` для превышения лимита, `500` для серверной ошибки. Наружу не отдавать stack trace и чувствительные пути.

## 9. Журналирование

Логировать: дату/время, IP, метод, оригинальное/итоговое имя, размер, SHA-256, app_version, device, transport и результат.

## 10. Защита

На стороне приложения отдельного секрета сейчас нет. Поэтому минимум:

- только POST;
- только поле `report`;
- лимит размера;
- валидация ZIP;
- без автоматической распаковки;
- защита от path traversal;
- хранение вне публичного web-root;
- не исполнять содержимое;
- при необходимости позже добавить rate limit/token.

## 11. Содержимое ZIP

Сервер не обязан понимать содержимое архива. Текущая версия может содержать:

- `README.txt`
- `summary.txt`
- `screen/channels.txt`
- `screen/switch_finder_current.txt`
- `switch_finder/history.txt`
- `scan/screen_scan.txt`
- `scan/full_scan.txt`
- `state/dynamic_snapshot.txt`
- `state/mapping.txt`
- `logs/session.log`
- `logs/runtime.log`

Список может расширяться; сервер не должен жёстко требовать конкретный набор файлов.

## 12. Критерии приёмки

Задача выполнена, если:

- `POST ?action=siyi_receive` работает;
- `$_FILES['report']` принимается;
- не-ZIP/пустой/слишком большой файл отклоняется;
- ZIP сохраняется в `/data/siyi/YYYY-MM-DD/`;
- имя содержит дату/время и исключает коллизии;
- считается SHA-256;
- возвращается JSON и HTTP 2xx при успехе;
- ошибки получают подходящий 4xx/5xx;
- ZIP не распаковывается и не меняется;
- путь нельзя подменить через имя или POST-параметры;
- событие журналируется.

## 13. Следующий этап
